The five frozen modules below are accepted for their stated finite scopes.
The actual seven-call generated constructor now has a proved one-step NO
cost and recurring deletion profile; its iteration proves both properties
from the lookup seed without assuming any future profile. The full-product
identity preserves the complete recursive labels, rational laws, and entry
evaluator for the graph activity named in that identity.

All five modules replayed successfully from independent private copies.

and `Quot.sound`. The NO proof graph uses the new weighted incoming theorem
and actual source/restoration bridges. No mathematical or compiler repair
was needed in this constructor packet.

There is one separate same-table boundary: the full identity is stated for
the graph's proof-side selector ordering. The randomized printer uses the
literal executable selector ordering. This packet alone does not transport
between them; that consumer needs the existing generic selector-conjugacy
theorems instantiated at the v42 widths. This is not a defect in the stated
identity, and this review does not certify the separately owned randomized
NO proof or its printed-table consequence.

## The constructor is the actual tuple-list construction

`V42GeneratedConstruction` instantiates the existing executable generic
constructor with

```
s=2^k, q1=s-2, q2=2^(b+2k), w=2^(8k), Q=2^(24k).
```

No colouring, NO promise, cost, deletion profile, desired output table,
runtime certificate or source-supplier parameter occurs in `numberedStep`,
`numberedIterate`, `storedStep`, `storedIterate` or `graphRun`.
They call `executableCodeD 8192`, whose output is the actual
`IndexedLaw.construct` array, its positive rational law, and its decoder.

The inherited generic definitions were read directly, not inferred from
their names. They construct these seven lists, in this order:

| Call | Width and original alphabet law |
| --- | --- |
| Gamma | `q1+s+1=2s-1`, base column law |
| Inner template | `q2`, uniform `q1` selector times base row law |
| Outer template | `s`, uniform `q2` selector times Gamma label law |
| Metadata stream | `w`, template-bin/item mixture with weights `255/256,1/256` |
| Base stream | `w`, base row law |
| Template-selector stream | `w`, inner-template label law |
| Final list | `Q`, uniform `w` selector times the actual two-family source-column law |

The two source-column families remain a disjoint tagged sum, including when
their decoded columns coincide. Every list index remains a label. The
stream label is the product of the **three complete list indices**, with
the product of their original rational laws; it is not a quotient by equal
decoded tuples. The final successor is exactly

```
successor j (a,label) = B (streamDecode label (finalDecode j a).1)
                          (finalDecode j a).2.
```

Its row law is the final-list law; its column law is uniform `Q` times the
complete-stream law. `SourceData.numbered` only numbers this product through
an explicit finite equivalence. It leaves all row indices and their weights
in place and reindexes the column weights through that same equivalence.
`numbered_cost` and `numbered_profile` therefore transfer the actual cost
and both deletion thresholds, rather than choosing a new hard presentation.

`StoredMatrix.ofNumbered_numbered` is equality of the whole numbered record,
including entry function and both rational laws. Each stored iteration is
the same executable step with Boolean cells and weight vectors materialized.
The new stored-to-numbered iteration identity preserves these complete data.

## One-step NO proof: allowed input and proved output

`V42GeneratedNo.successor_no` accepts:

- The graph's positive size/edge count, positive fixed gap and degree constants,
  looplessness, maximum degree, and the explicit violated-edge gap for every
  three-colouring.
- The actual repeated edge-coordinate width equality.
- A sufficient public numerical cutoff.
- The **current base** matrix's exact cost `D R=d>=2` and its current
  two-threshold deletion profile at `rho=s^-4`.
- Actual indexed tuple lists with exact order-8192 marginals and their laws,
  as supplied by the generic `SourceData`/stream/final-list interface.

The last interface contains no matrix-cost or target-profile assertion.
The executable `numberedStep_no` then selects the actual Code D outputs;
its caller supplies no source lists or source supplier.

The proof derives the template costs/profiles from the current base profile,
then derives the source's near-full lower bound on the literal `SourceData.B`
using the graph gap. Its source upper bound is unconditional. It invokes the
new numerical guard theorem and the same-source indexed alignment/restoration
theorem to obtain, on the actual `src.successor`,

```
D(next R) = d+40k+1,
TwoThresholdProfile(next R, rho, d+40k+1).
```

There is no desired successor profile, receiving inequality, conservation
conclusion, or target cost among these premises.

The numerical substitution is exact:

```
source cost C = d+k+(4k+2k)+k+1 = d+8k+1,
internal interlace adds 8k,
final restoration adds 24k,
total increment = 40k+1.
```

The universal increment is `h+1` and the YES increment is `h`, where the
generic literal overhead is `h=b+36k`. In the generated case `b=4k`, this
is exactly `h=40k`. The extra universal bit comes from
`clog2(q1+s+1)=k+1`, while the YES protocol has
`clog2(q1+2)=k`.

## Iteration and the lookup seed

`numberedIterate_no` proves exact cost and the recurring profile by induction
on the number of rounds. In the successor case it calls `numberedStep_no`
with the cost and profile proved by the induction hypothesis. The parameters
and graph activity remain fixed. The zero-round case is exactly the input
matrix and base profile, so no positive-round assumption is hidden.

`storedIterate_no` transfers both conclusions through the whole-record
stored-to-numbered equality. `graphRun_no` then starts from the actual
stored lookup seed at `L_g=4k`. Its cost and profile come from
`storedLookupSeed_cost` and `storedLookupSeed_profile`; the seed profile is
not a caller premise. Its nonempty carriers and cost at least two follow
from the lookup width and `k>=2`.

With `i` denoting rounds, the final graph run satisfies

```
d0 = LookupSeed.exponent(4k)+1,
B_i = d0+i*(40k),
H_i = B_i+i = d0+i*(40k+1),
D(R_i)=H_i and TwoThresholdProfile(R_i,rho,H_i) in the NO case,
D(R_i)<=B_i in the YES case.
```

The lookup exponent is the ceiling log of `64(L_g+1)`, so this is the
manuscript's exact `pow2Ceil(64(L_g+1))` seed. The NO graph theorem has no
base-profile premise left; the YES theorem uses the same `graphRun`.

The top generated theorem still exposes the width equality and cutoff as
arithmetic premises. They are supplied by the reviewed fixed graph-promise
cutoff and least-dyadic schedule in the public consumer, rather than by a
new assumption about matrix hardness. This review does not by itself
certify the external Dinur/BOT source records.
